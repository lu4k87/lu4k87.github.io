UX-Regeln im Code
Sicherheit

Sicherheit liegt nicht im Browser

  • Remote-Gamepad: WLAN weg oder Tab verdeckt → kein Heartbeat → Watchdog stoppt selbst
  • Kollisionsvorprüfung, Servo und E-STOP laufen auf dem Server
Sicherheit

Wer steuert, ist eindeutig

  • Zuschauen: beliebig viele Geräte · Bewegen: nur der Inhaber des Control-Locks
  • Prüfung Remote-Gamepad: Server · UI-Buttons, Jogging, VR: Browser (motionAllowed)
  • Robot | Hardware: Remote-Gamepad braucht zusätzlich eine Freigabe
Bewegung

Planen vor Ausführen

  • Zielpose wird erst geplant und als Bahn gezeigt
  • Fahren erst nach Bestätigung (/ui/confirm_moveto_preview)
Zustand

Ein Zustand, viele Ansichten

  • VR-Handgelenk-Panel spiegelt die DOM-Buttons der Desktop-Seite
  • Logik existiert nur einmal
Layout

Layout gehört dem Nutzer

  • Sektionen zwischen Spalten ziehen
  • HUD-Tabs andocken, Presets speichern
  • Nichts überlappt, nichts wird gequetscht
Rückmeldung

Fehler enden sichtbar

  • Stream ohne Kamera: 5 Versuche mit wachsendem Abstand
  • Danach „Try again“ statt stillem Weiterlaufen

Regeln im Node

  • Neue Anweisung während THINKING/RUNNING → busy, wird abgelehnt
  • Neue Anweisung, während ein Plan wartet → ersetzt den Plan
  • Execute zählt nur mit passender id
  • Plan wird vor jeder Bewegung geprüft; Fehler gehen ans Modell zurück (max. 2 Korrekturen)
  • Robot | Hardware ohne allow_real_motion → preview (nur Plan) · virtuelle Objekte nie · jeder Plan wartet auf Execute
  • E-STOP aktiv → nichts wird ausgeführt
  • Fehler eines Schritts → replan: der Agent sieht Fehler und neue Szene und plant neu (max. 2×), sonst error mit Schritt und Grund

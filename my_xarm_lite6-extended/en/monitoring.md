## 8. 📊 Monitoring Dashboard

The **Monitoring Dashboard** (port 8083) is the platform dashboard for system, usage and evaluation. It replaces the older Dashboard Monitoring UI (port 8084, static code analysis + node monitor), which was removed on 2026-09-28 (still in the Git history).

### 📈 Monitoring Dashboard (Port 8083)
Web dashboard for system load, ROS 2 communication, robot usage and user sessions – and the data basis for evaluating user studies (package `http_monitoring_dashboard_p8083`).

*Top: **Overview** – health line, tiles CPU/RAM/GPU/ROS 2, system load, *Today* (motions, grasps, UI clicks), *Robot now* and *UIs & services*; **ROS graph** – nodes via topics with live rates and the node list per group (31 nodes of the FAKE stack). Bottom: **Robot usage** – MoveIt runs, success rate, duration and planning time, results and time shares; **Evaluation** – usability test *Pick & Place – input methods* from the template with flow strip, KPI row and task A1 with its input methods. The interface language follows the browser (here German).*

- **Monitoring:** overview (N18.2/N18.14: a health line on top names only deviations – E-stop, failed services, CPU/RAM above the thresholds; services that were never started are a grey hint, green only when nothing deviates – then four tiles CPU, RAM, GPU, ROS 2 and a 8 + 4 grid: load, *Today* (motions, grasps, clicks of the last 24 h, with an empty state instead of zeros), network, events on the left, *Robot now* and the 5 most important services with “+ n more” on the right), system (CPU, RAM, GPU/VRAM, temperatures, network), processes, UIs & services (reachability of all web UI ports).
- **ROS 2:** ROS graph – nodes and topics as a graph with live rates (via topics or node → node, focus mode; ordered: one frame per node group, groups sorted by data flow from left to right, topics in the lane between sender and receiver, line colour = sending group, button *Neu anordnen* resets moved nodes, `js/graph.js`) and topics with Hz and bandwidth of selected topics (sampled raw, without deserialising).
- **Usage:** robot usage (MoveIt runs, jog and gamepad time, gripper, E-stops, grasp and VLA commands, joint travel, **blackbox incidents**: per saved rosbag2 in `~/.ros/blackbox` time, trigger, window, messages, topics and size, a button copies `ros2 bag play <folder>`; API `/api/blackbox?range=`), grasp & place, users & sessions (UI clients via `/remote/heartbeat`, owner via `/remote/control_state`, rosbridge WebSocket clients).
- **Evaluation – usability tests:** hierarchy *usability test → tasks → participants → questionnaires*.
  - **Usability tests:** a test groups tasks (e.g. several pick-and-place tasks); each task has instructions, a success criterion, a target time and **input methods** (e.g. gamepad, VR (Quest 3), Robot Control UI, gaze + voice, VLA-M). *Add participant* (existing or new with ID + name) plans one **run** per method with its own evaluation ID (`P01-E03`); the order of the methods is **counterbalanced** per participant (balanced Latin square / Williams design by participant number: every method equally often first and equally often after every other one) against order effects. Template *Pick & Place – input methods* with five example tasks.
  - **Test header:** flow strip with five steps (*tasks → questionnaires → participants → runs → questionnaires filled*; tick = done, yellow = missing). If questionnaires are missing, *SEQ + SUS* creates SEQ after every task and SUS once per participant from the templates (`POST /api/study/test_questionnaires_default {study_id}`). The KPI row below shows results only: tasks completed, task time (median), operating errors, questionnaire score mean.
  - **Run:** *Start* / *Stop* set markers; motions (success, planning time), grasps, UI clicks, gamepad buttons, jog/motion time, warnings and connected clients are attributed to the run and stored when it ends (kept beyond the 30-day retention). The test lead records *completed / not completed*, operating errors and notes. Only one run can be active at a time (the metrics cover the whole system). *Device of the participant* at the start: UI clicks and grasps then count only from that client (motions, gamepad buttons and jog time carry no sender and still count for everyone); the run shows „counts only …“. *Start* in the tables picks the device currently in control (Robot Control UI holding the control lock), otherwise all devices count. The **Test running** bar names the counted device („counts <device>“ / „counts all devices“) and shows live motions · grasps · UI clicks · gamepad buttons (~6 s); live values and the final result use the same device filter. *Participants* tab: the run table has *Start* / *Stop* / result, a click opens the run detail; a warning appears when no Robot Control UI is connected. While a run is active the Monitoring Dashboard publishes it latched on `/dashboard/eval_run` (JSON `eval_id`, task, method, device; `{}` afterwards) and the Robot Control UI shows an **Eval** chip with the ID in the header; in VR the HUD shows it as a `TEST <id>` badge on the TELEMETRY card. At the start every Robot Control UI shows a **Usability test starts** popup (participant code + name, task x/y, run x/y with method, target time, short description, criteria) with *Confirm*; *Confirm* signs the tab in as the run's participant if nobody is signed in yet and the run counts for this device. Participants can also sign in themselves via the **Participant** pill in the status bar (ID like `P01`, kept per tab); the code goes out as `participant` in the heartbeat and the Monitoring Dashboard starts a new session for that person.
  - **Questionnaires:** custom questionnaires with seven question types (Likert scale, slider, single/multiple choice, yes/no, number, free text) or templates SUS, NASA-TLX (raw), UEQ-S, SEQ, demographics (validated questionnaires keep fixed items). Assigned *per run* (preselected per task) or *once per participant* (per test); later changes also apply to runs already planned (deselected open questionnaires are removed, started ones stay). Filled in a focus view without navigation – on the PC or via link on a tablet (`#fill/<id>`); afterwards it jumps to the next open questionnaire. **Tablet link** in the participant header (`#fill/p<id>`, kiosk): shows only this participant's open questionnaires one after another, without a way back into the evaluation; if none is open it waits and checks every 5 s. Scores (SUS 0–100, TLX, UEQ-S pragmatic/hedonic, SEQ, mean 0–100 %) are computed automatically.
  - **Checks in the flow:** the flow strip of a test warns when a questionnaire is assigned per task **and** per participant (*Doppelte entfernen* removes it from “per person” and deletes only the still open assignments) and when runs were started without a device (*Gerät nachtragen*: pick the device from the sessions in the time window → KPIs are recomputed and the session is linked to the participant).
  - **Usage data per participant:** card *Nutzungsdaten* in the participant detail. All sessions (Robot Control UI, Touch Panel …) are linked: automatically via the device of a run (start/stop), via login with the participant ID in the Robot Control UI (heartbeat `participant` → `sessions.participant`) or manually. *Vorgeschlagen* lists unlinked sessions on the test day (same device or up to 2 h before the first run, e.g. briefing, practice) – linking only by click. Shows usage, practice and control time, clicks, gamepad buttons, motions, grasps, a timeline of the test day (practice · sessions · runs) and used sections. Stored in `participant_sessions`; sessions are kept beyond the 30-day retention.
  - **Analysis (report):** tab *Auswertung* per usability test, structured after ISO 9241-11: KPI row (participants, runs, tasks completed, task time, SUS, data quality = open questionnaires, runs without device or rating), jump bar and six chapters – *1 Effectiveness* (success rate per method, matrix task × method), *2 Efficiency* (task time per method as box with dots and target time, operating errors and failed motions, median time per task relative to the target time), *3 Satisfaction* (SUS per method on the Bangor scale with 95 % confidence interval, NASA-TLX profile, UEQ-S, SEQ per task), *4 Learning* (order effect by position of the method, practice time ↔ task time), *5 Usage data* (UI clicks, gamepad buttons, jog time, grasps per method, used sections), *6 Participants* (matrix person × task with questionnaires, practice and usage time, free texts and notes, export). *Bericht drucken / PDF* prints in light theme without navigation. Data: `GET /api/study/report?study=<id>`. Per participant also runs, sessions, learning curve and task time. Export as CSV/JSON (answers per questionnaire with one column per question; runs include the participant's usage data `person_*`).
  - **Marker sections:** the *Marker* button splits the recording freely into sections; the tab compares them side by side – success rate, motion and planning time, grasps, holding time, UI clicks, gamepad buttons, jog and motion time, warnings, CPU.
  - Data lives in the same SQLite file (tables `studies`, `eval_tasks`, `participants`, `eval_runs`, `questionnaires`, `responses`) and is not removed by *Clear statistics*.
- **Setup:** the *Setup* button opens a centred overview card (blurred background, Esc closes, section jump links at the top and a **DE / EN** switch, remembered): first the system overview clients → server → robot (Touch Panel, laptop/tablet, Quest with their address; server = this PC, in the lab or at home, with the Nexus switches *Remote access* and *Localhost only* and `tools/firewall_setup.sh`; xArm with REAL and FAKE), then IP assignment per network (home network, robot LAN with the fixed robot IP, Tobii), web addresses of all UIs as links (with the current server IP), ports with protocol, touch display (Touch Panel: saved display output live, lab setup `DP-5`/`DP-6`, touch controller, `--list`/`--output`, hint when touches land on the main monitor), HTTP vs. HTTPS/SSL for VR and gamepad (accepting the certificate), VLA-M (data flow UI → rosbridge → `vla_bridge` → MoveIt/gripper, `/vla/*` topics, policies, REAL lock, live whether Ollama and `qwen2.5:14b` are installed on this PC, otherwise a warning with the install command). Networks are marked the same way everywhere (home network, Robot-LAN, Tobii, localhost), the web addresses show *IP or localhost* in front of the port. Live from `/api/network`: addresses from `config/network.yaml` and this PC's IPs – a missing network card in the robot LAN shows a warning. *Export as PDF* opens the browser's print dialog (destination "Save as PDF", scaled to one A4 portrait page, light, without buttons, in the chosen language). The same card (`ui_shared/net_info.js`) is available in the Nexus Webapp.
- **UI clicks:** the Robot Control UI counts clicks on buttons and chips and changed inputs and sends them every 3 s on `/ui/interaction_events` (`js/usage_stats.js`) – only label and area, never input values.
- **Storage:** 1-s samples of the last hour in memory; minute averages (30 days), motions, sessions, usage counters and events in SQLite (`~/.local/share/monitoring_dashboard/monitoring.db`). All topics are optional – without a publisher a counter simply stays at 0.
- **Display:** time range 5 min – 24 h, refresh rate (Evaluation fixed at 1 s, selector hidden there), live mode, **theme** (button *Dark / Light / Jarvis / Nord Blue ▾* in the top bar or **Alt+T** anywhere: list with live preview – ↑↓ preview, Enter apply, Esc cancel, 1–4 direct; *Jarvis* = dark HUD look with cyan glow, grid and Orbitron headings; *Nord Blue* = calm slate grey with frost blue, matt, no glow; same list as Robot Control UI and Nexus Webapp, this browser only), page zoom − / value / + (70–150 %, click the value = 100 %, this browser only), **language** German / English (row *Language DE | EN* at the bottom of the theme list or key **L** there; switches live, numbers and dates follow; without a saved choice the browser language; this browser only, dictionary `i18n/en.json`).

```bash
ros2 launch http_monitoring_dashboard_p8083 monitoring_dashboard.launch.py   # port:=8083 open_browser:=true db:=<SQLite file>
# → http://localhost:8083/ · Nexus Webapp: card "Monitoring Dashboard" in RUN DEV SETUP and SERVER SETUP
```

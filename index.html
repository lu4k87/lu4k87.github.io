03Arbeitsweise

Ein Workflow für alle Projekte

Regeln, Skills, Agenten, Hooks, Memory, TODOs und Übergaben liegen zentral im Haupt-Repo. Pull-Bahnen bringen sie auf jeden Rechner und in jedes Projekt, Push-Bahnen veröffentlichen das Ergebnis.

01

Haupt-Repo · einzige Quelle

GitHub · privat · Checkout ~/dev_ws

Alles, was die KI-Werkzeuge brauchen, liegt versioniert in Git – Regeln, Wissen, Gedächtnis, Automatik und Koordination.

Regeln

  • AGENTS.mdProjektregeln des Haupt-Repos (Sicherheit zuerst, Vorrang vor den gemeinsamen Regeln)
  • .claude/common/RULES.mdGemeinsame Regeln für alle Projekte: Antwortformat, Rollen, UI-Grundregeln, Skill-Finder
  • .claude/ROLES.mdRollenkarte: Designer, Entwickler, Prüfer, Synchronizer …

Wissen (bei Bedarf geladen)

  • .claude/skills/0 Skills (0 davon global), gefunden über die Finder-Tabelle in RULES.md
  • .claude/agents/0 Agenten für Prüfung, Suche, Tests, z. B. safety-reviewer
  • .claude/repertoire/Wiederverwendbare Bausteine für Vorschauen und Szenen

Gedächtnis

  • .claude/common/memory/Gemeinsame Memory: wer der User ist, Arbeitsweise (gilt in allen Projekten)
  • .claude/memory/Memory des Haupt-Repos; Claude schreibt direkt hierhin
  • .claude/handoff/Übergaben: Starttext für „chat weiter …“ im neuen Chat

Automatik

  • .claude/hooks/0 Hook-Skripte: Antwortformat, Schutz vor Gefährlichem, Claims, Lagebild
  • .claude/settings.jsonVerdrahtet Hooks mit Ereignissen (vor/nach Werkzeug, Start, Ende)
  • tools/pre-commitPrüft jeden Commit (Tests, Begriffe, Format)

Koordination

  • TODOS.mdBacklog + Abschnitt „In Arbeit“: Claims paralleler Chats, per Git für alle sichtbar
  • config/projects.yamlProjektliste: Ordner, Repo, Karte auf dieser Seite

Erzeugt für Codex + Gemini

  • .codex/.agents/Aus .claude/ erzeugt von tools/agents_sync.py, nie von Hand ändern

Pulltools/ws_sync.shgleicht ab und verlinkt global

  1. git pull --rebase --autostash holt den neuen Stand
  2. Memory + Benutzer-Settings einrichten
  3. agents_sync.py --home verlinkt Regeln, Skills, Agenten in ~
  4. codex_setup.py gibt Codex-Hooks frei
  5. colcon build nur für geänderte ROS-Pakete

Pushgit commit → git pushveröffentlicht den fertigen Stand

  1. tools/pre-commit prüft den Commit
  2. Skill commit macht Commit + Push nach jeder Aufgabe
  3. claim.py pusht Claims in TODOS.md sofort

So greift es ineinander: ein Chat von Start bis Push

Hooks, Skills, Agenten, Memory und TODOS arbeiten in dieser Reihenfolge zusammen – ohne dass der User etwas verdrahten muss.

  1. Start
    session_overview.pyLagebild: parallele Chats, Claims, offene Übergaben. Regeln + Memory-Index sind schon geladen.
  2. Anfrage
    chat_length_hint.pyErinnert an passende Skills aus der Finder-Tabelle und an einen neuen Chat bei langem Kontext.
  3. Arbeit
    todo_claim_hook.py · pre_tool_guard.pyErste Änderung trägt einen Claim in TODOS.md ein; Schutz prüft jeden Befehl; Agenten prüfen Ergebnisse.
  4. Antwort
    post_edit_check.py · format_check.pyJede Datei wird sofort geprüft; am Ende prüft der Stop-Hook das Antwortformat.
  5. Abschluss
    chat_handoff.pyCommit + Push (siehe Bahnen oben), Claim wird gelöscht; Rest als Übergabe in .claude/handoff/.

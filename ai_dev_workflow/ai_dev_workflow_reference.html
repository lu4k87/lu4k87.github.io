01Werkzeugkasten

Skills, Agenten, Hooks und Skripte greifen ineinander

Skills tragen das Wissen, Agenten sind dünne Hüllen, die einen Skill laden und isoliert arbeiten, Hooks setzen Regeln durch, Skripte liefern den Beleg. Suchen oder Element berühren zeigt Verbindungen.

Skills51

Je Thema ein SKILL.md, Skripte und Vorlagen daneben. Geladen nur bei Bedarf, einmal je Chat.

Dünne Hülle aus Rolle, Modell, Tools und Rückgabe; das Wissen kommt aus dem Skill. Lange Logs bleiben aus dem Haupt-Chat.

Hooks5 Ereignisse + Git

Laufen automatisch an fünf Ereignissen eines Chats (Start, Prompt, vor und nach jedem Werkzeug, Antwortende) und beim Commit; sie setzen Regeln durch, die man sonst vergisst – mit eigener Testsuite.

Skriptetools/ + bin/

Liefern den Beleg vor „fertig“. Wiederverwendbare Skripte in tools/, Einmal-Skripte nur im Scratchpad.

Kein Treffer – probier ui, test, vla oder review.

Einrichten, prüfen, abstimmen

cd ~/dev_ws
# Einmal je Rechner; installiert keine KI-Clients
tools/ws_sync.sh --setup
# Codex: Trust-Status nur lesen
python3 tools/codex_setup.py --check
# Vor parallelen Änderungen
git status --short
python3 tools/claim.py list --fetch
# Chat-Kennung aus dem Start-Lagebild einsetzen
python3 tools/claim.py start --who <chat-id> \
  --task "[Bereich] Ziel" --files "pfad (Abschnitt)"
# Nach geprüftem Commit + Push
python3 tools/claim.py done --who <chat-id>
Claude Code

.claude/settings.json: Projekt-Hooks. ws_sync.sh --setup überträgt Memory und Benutzer-Settings; danach neu starten.

Codex

.codex/hooks.json → codex_bridge.py. Projekt und Prüfsummen der Hooks müssen als vertrauenswürdig markiert sein (Trust); nach Änderungen erneut prüfen.

Antigravity / Gemini

GEMINI.md und .agents/ teilen Regeln, Skills und Memory. Pre-/Post-Adapter: .agents/hooks.json; Aktivierung im Client prüfen.

Rechnerwechsel

Eigene fertige Arbeit pushen. tools/ws_sync.sh nur abgestimmt ohne laufende Edits: Pull mit Rebase/Autostash und Build geänderter ROS-Pakete.

04Begriffe

Jeder Begriff in einem Satz

Die Wörter, die die Workflow-Seiten benutzen – erklärt für Leser von außen.

Haupt-ChatDer Chat, mit dem der User spricht; er beauftragt Agenten und prüft deren Ergebnis.
SkillAnleitung zu einem Thema (SKILL.md + Skripte), die ein Chat nur bei Bedarf lädt.
AgentHilfs-Chat mit eigenem Kontext für einen Einzelauftrag; gibt nur das Ergebnis zurück.
HookSkript, das an festen Stellen eines Chats automatisch läuft und prüft, warnt, fragt oder blockiert.
Stop-HookHook am Ende jeder Antwort; format_check.py prüft dort das Antwortformat.
BridgeÜbersetzer-Skript, mit dem dieselben Hooks auch in Codex und Antigravity laufen.
TrustFreigabe in Codex, dass Projekt und Hooks laufen dürfen; nach Änderungen an Hooks neu nötig.
LagebildÜbersicht beim Chat-Start: laufende Chats, fremde Änderungen, offene Übergaben.
Datei-RegisterListe, welcher Chat welche Datei uncommittet geändert hat – nur dieser Rechner, live.
ClaimZeile „🔒 In Arbeit“ in TODOS.md: dieser Chat bearbeitet diese Dateien – per Git auf allen Rechnern sichtbar.
ÜbergabeDatei in .claude/handoff/, mit der ein neuer Chat per „chat weiter <kennung>“ weitermacht.
ScratchpadArbeitsordner eines Chats für Einmal-Skripte und Zwischenstände; nie im Repo.
Prüfstufe0 trivial bis 3 kritisch; legt fest, wie tief vor „fertig“ geprüft wird.
Ponytail-LeiterReihenfolge vor jedem Code: Braucht es das? Gibt es das schon? Stdlib? Plattform? Erst dann neuer Code.
EffortDenktiefe des Modells (low … max): höher = gründlicher, aber teurer.
vorgemerkt (staged)Mit git add für den nächsten Commit ausgewählte Dateien.
Fast-ForwardPush, der nur neue Commits anhängt und nichts im Verlauf überschreibt.
Domain 94 / 97Eigene ROS-Kanalnummer (ROS_DOMAIN_ID) für Tests, damit der laufende Roboter-Stack ungestört bleibt.
Robot | Digital TwinSimulierter Roboter am Bildschirm; hier darf jeder Chat testen.
Robot | HardwareEchter Roboter; bewegt sich nur nach Freigabe des Users in diesem Chat.
